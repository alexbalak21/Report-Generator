# Creating Your Own Report Profile

This guide walks you through building the three files a report profile needs:

1. **`data.xlsx`** — your data
2. **`template.docx`** — your Word template
3. **`mapping.json`** — the file that connects the two

---

## 1. The Excel data file (`data.xlsx`)

- Row 1 must be the **header row** — one column name per field.
- Every row after that is one sample/report.
- Column names can contain spaces and accents (`nom entreprise client`, `température`, etc.) — just be consistent, since the mapping file will reference them exactly.

**Example — `data.xlsx`**

| date rapport | nom entreprise client | appellation produit | numero echantillon | imp |
|---|---|---|---|---|
| 21/06/2026 | ACME Corp | Steak haché | 001 | 0.12 |
| 21/06/2026 | ACME Corp | Filet de poulet | 002 | 0.08 |

> Tip: If you need lookup tables (e.g. species code → French name, supplier → approval number), add them as **extra sheets** in the same workbook. You'll reference them by sheet name in the mapping file (see [Lookups](#lookup-cross-sheet-reference) below).

---

## 2. The Word template (`template.docx`)

- Write the report exactly as you want it to look — text, tables, headers, footers, formatting, logos, everything.
- Anywhere you want a value from Excel inserted, put a placeholder tag: **`{{placeholder_name}}`**.
- Use only letters, numbers, and underscores inside the tags — no spaces or accents (accents are technically allowed but underscores are safer and match the examples below).

**Example — inside `template.docx`**

```
Report No.: {{numero_rapport}}
Date: {{date_rapport}}

Client: {{nom_entreprise_client}}
Product: {{appellation_produit}}

Sample: {{numero_echantillon}}
IMP: {{imp}}
```

Each `{{...}}` tag must have a **matching entry** in the mapping file below — matching means the text inside the tag (e.g. `numero_rapport`) equals the `"placeholder"` value defined in the mapping, minus the double braces.

> ⚠️ The single most common mistake: a placeholder in the template that doesn't exactly match the mapping's `"placeholder"` key. `{{n_ech}}` ≠ `{{numero_ech}}` — the app won't fill either one if they don't match exactly.

---

## 3. The mapping file (`mapping.json`)

This is a plain JSON file. Each entry tells the app *where a value comes from* and *which placeholder to put it in*.

### 3.1 Simple column mapping

The most common rule — copy a value straight from an Excel column into a placeholder.

```json
"nom entreprise client": {
  "column": "nom entreprise client",
  "placeholder": "{{nom_entreprise_client}}"
}
```

- `"column"` — the exact Excel header name.
- `"placeholder"` — the exact tag used in the `.docx` template (with `{{ }}`).
- The key on the left (`"nom entreprise client"`) is just a label for this rule — it can match the column name for clarity, but doesn't have to.

### 3.2 Computed fields (no Excel column involved)

Some values are generated by the app itself rather than read from a column. These use `"operation"` instead of `"column"`.

**Today's date:**

```json
"date_du_jour": {
  "operation": "today",
  "format": "%d/%m/%Y",
  "placeholder": "{{date_du_jour}}"
}
```

**Auto-numbered report ID** (`yymmdd-N`, e.g. `260621-3`):

```json
"numero_rapport": {
  "operation": "excel_day_counter",
  "date_column": "date rapport",
  "sample_column": "numero echantillon",
  "date_format": "%d/%m/%Y",
  "placeholder": "{{numero_rapport}}"
}
```

> Note: always include `"placeholder"` on computed fields if you want the value to appear in the document body. Without it, the value is still calculated internally (e.g. for use in the filename) but won't be inserted anywhere in the template.

### 3.3 Operations (transforming a column value)

Add an `"operations"` list to a column mapping to transform the raw value before it's inserted. Operations run **in order**.

| Type | What it does | Extra key |
|---|---|---|
| `date_format` | Reformats a date | `"format": "%d/%m/%Y"` |
| `multiply` | Multiplies a number | `"value": 100` |
| `divide` | Divides a number | `"value": 100` |
| `add` / `subtract` | Adds/subtracts a number | `"value": 10` |
| `round` | Rounds to N decimals | `"decimals": 0` |
| `suffix` | Appends text | `"value": "%"` |
| `prefix` | Prepends text | `"value": "Lot n° "` |
| `upper` / `lower` / `strip` | Case/whitespace cleanup | — |
| `replace` | Find-and-replace text | `"find": "...", "replace": "..."` |
| `formula` | Placeholder no-op — used when the Excel cell already contains a computed formula value | — |

**Example — show a decimal Excel value (`0.12`) as a rounded percentage (`12%`):**

```json
"imp": {
  "column": "imp",
  "placeholder": "{{imp}}",
  "operations": [
    { "type": "multiply", "value": 100 },
    { "type": "round", "decimals": 0 },
    { "type": "suffix", "value": "%" }
  ]
}
```

**Example — reformat a date column:**

```json
"dlc": {
  "column": "dlc",
  "placeholder": "{{dlc}}",
  "operations": [
    { "type": "date_format", "format": "%d/%m/%Y" }
  ]
}
```

### 3.4 Lookup (cross-sheet reference)

Use `"operation": "lookup"` to pull a value from a **different sheet** in the same workbook — e.g. translating a code into a readable label.

```json
"espece_nom": {
  "operation": "lookup",
  "sheet": "especes",
  "key": "nom_latin",
  "match": "espece",
  "value": "nom_francais",
  "placeholder": "{{espece_nom}}"
}
```

This means: *take the value of the `espece` field from the current row → find the row in the `especes` sheet where `nom_latin` equals that value → return its `nom_francais` column.*

For multi-step lookups (a chain of joins across several sheets), use `"operation": "lookup_join"` with a `"steps"` list — see the code comments in `app/core/processors.py` for the full syntax if you need this.

### 3.5 File name rule

Controls what the generated `.docx` is called when saved.

```json
"file_name": {
  "name": "ACME Rapport d'essai",
  "operation": "format",
  "format": "{name} {numero_rapport}.docx"
}
```

This uses Python-style `{field}` substitution, pulling from any other field already computed in the mapping (like `numero_rapport` above) plus its own `"name"` key.

### 3.6 Config block

Add this once at the top of the mapping file. The app fills these in automatically as you use it, but it's good to know they're there:

```json
"config": {
  "data_file": "C:/Reports/data.xlsx",
  "template_file": "C:/Reports/template.docx",
  "output_dir": "C:/Reports/output",
  "date_format": "%d/%m/%Y"
}
```

## 4. Putting it all together — minimal working example

**`data.xlsx`**

| date rapport | nom entreprise client | appellation produit | numero echantillon |
|---|---|---|---|
| 21/06/2026 | ACME Corp | Steak haché | 001 |

**`template.docx`**

```
Report No.: {{numero_rapport}}
Date: {{date_du_jour}}

Client: {{nom_entreprise_client}}
Product: {{appellation_produit}}
```

**`mapping.json`**

```json
{
  "config": {
    "data_file": "C:/Reports/data.xlsx",
    "template_file": "C:/Reports/template.docx",
    "output_dir": "C:/Reports/output",
    "date_format": "%d/%m/%Y"
  },
  "nom entreprise client": {
    "column": "nom entreprise client",
    "placeholder": "{{nom_entreprise_client}}"
  },
  "appellation produit": {
    "column": "appellation produit",
    "placeholder": "{{appellation_produit}}"
  },
  "date_du_jour": {
    "operation": "today",
    "format": "%d/%m/%Y",
    "placeholder": "{{date_du_jour}}"
  },
  "numero_rapport": {
    "operation": "excel_day_counter",
    "date_column": "date rapport",
    "sample_column": "numero echantillon",
    "date_format": "%d/%m/%Y",
    "placeholder": "{{numero_rapport}}"
  },
  "file_name": {
    "name": "ACME Rapport d'essai",
    "operation": "format",
    "format": "{name} {numero_rapport}.docx"
  }
}
```

Select row 1 in the app → the generated file will be named `ACME Rapport d'essai 260621-001.docx` and contain:

```
Report No.: 260621-001
Date: 12/08/2026

Client: ACME Corp
Product: Steak haché
```

## 5. Checklist before you generate

- [ ] Every Excel header used in `"column"` matches spelling and spacing exactly.
- [ ] Every `{{placeholder}}` in the `.docx` template has a matching `"placeholder"` value in `mapping.json`.
- [ ] Computed fields you want visible in the document have a `"placeholder"` key (not just used internally, e.g. for the filename).
- [ ] Lookup sheets referenced in `"sheet"` actually exist in the workbook, with the right column names.
- [ ] `"config"` paths point to the right files (the app updates these automatically once you select files in the UI, so this is usually only relevant if you're hand-editing the JSON).
